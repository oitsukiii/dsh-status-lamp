# DSH 状态灯

一个桌面小挂件，一眼看出 DSH 此刻在干什么：在推理、在跑命令、在等你审批，还是已经完事了。

不用切窗口，不用看日志，余光扫一下就行。

> **开发方式**：本项目由 **DSH**（DeepSeek Harness）驱动 **DeepSeek V4.1 Flash** 以 vibecoding 方式完成 —— 全程靠对话描述需求、跑起来看、发现问题再改。素材（三色灯精灵图）由 ComfyUI 生成，再用 `tools/` 下的脚本裁切、去凸起、改未亮灯泡的颜色。

### 灯语

| 灯 | 含义 | 什么时候亮 |
|---|---|---|

## 2. 配置细节

### 右键菜单

![右键菜单](docs/images/menu-zh.png)

| 选项 | 作用 |
|---|---|
| **立即刷新** | 强制重新取一次状态，不等下一次推送 |
| **回到右下角** | 灯被拖到看不见的地方时用它找回来 |
| **始终置顶** | 是否浮在所有窗口之上 |
| **任务完成时播放提示音** | 一轮结束时响一下 |
| **灯光呼吸效果** | 点亮的灯泡在 60%~100% 亮度之间来回，到最亮停 1 秒 |
| **灯的大小** | 小 / 中 / 大三档，选了立刻生效 |
| **设置…** | 打开下面的配置窗口 |
| **退出** | 关掉灯 |

**这些都立刻生效并自动存盘**，不需要点保存。

### 设置窗口

![设置窗口](docs/images/settings-zh.png)

| 项目 | 说明 |
|---|---|
| **语言 / Language** | 中文 / English，切换后界面立刻变 |
| **插件地址** | 灯唯一的必需配置。本机填 `http://127.0.0.1:3099/events`；DSH 在别的设备上就填那台机的局域网 IP |
| **测试连接** | 请求一次桥的 `/state`，只验证网络能不能通 |
| **如何安装插件并配置** | 两种装桥的方式：让 agent 代劳（复制提示词），或手动装（复制项目地址） |

**桥的装法**（装在哪台机器上，灯就填哪台机的地址）：

| | 怎么装 | 特点 |
|---|---|---|
| **DSH 插件**（推荐） | 在 DSH 的「插件」页添加 `github:oitsukiii/dsh-status-lamp#path:/packages/dsh-lamp`，重启 DSH | 随 DSH 起停，不用管进程；直接订阅会话事件，**最快** |
| **Python 桥**（备选） | 见 [`docs/python-bridge.md`](docs/python-bridge.md) | 不用重启 DSH；但要装 Python 和 zstd 解码器，还得自己守住进程 |

两者对外接口完全一致，灯的配置不用改。

## 3. 快速开始

### 直接下载（Windows）

[**下载 DSH-Lamp.exe**](https://github.com/oitsukiii/dsh-status-lamp/releases/latest) —— 不需要装 Python，双击就能跑。

### 从源码跑

Python 3.9+，另外：

- **Pillow** —— 显示图片素材（没有就退回画一个圆点）
- **zstd 解码器** —— 只有用 Python 桥时才需要；插件版不需要
  - Python 3.14+ 自带
  - 否则 `pip install pyzstd`
  - 设置窗口里有一键安装按钮（仅 Python 桥模式下出现）

```bash
git clone https://github.com/oitsukiii/dsh-status-lamp.git
cd dsh-status-lamp
pip install pillow
python client/lamp.py
```

启动后右键灯打开设置。

## 4. 一些技术细节

### 状态是怎么判断的

DSH 会写两样东西：

| 数据 | 位置 | 特点 |
|---|---|---|
| 状态快照 | `~/.dsh/storages/session_projcache/sessions/*.json` | 结构化，但**写得很懒**（几十秒一次） |
| 事件日志 | `~/.dsh/sessions/<项目>/<会话>/session.v4.jsonl.zstd` | 写得勤，但压缩过、几百 MB |

**插件版**直接订阅 `session/event`，事件一提交就能看到 —— 不用轮询、不用解压。
**Python 桥**退一步：轮询快照 + 解压事件日志尾部补细节，因此会受 DSH 落盘时机影响。

事件日志在 Python 桥里是「跳到文件尾部找帧头、只解压最后几百 KB」的方式读的，不整份解压。

### 关于「已读」

**做不到，DSH 里没有这个概念。**

查过的位置：

| 找什么 | 结果 |
|---|---|
| `unread` / `markRead` / `lastRead` 之类的字段 | 只有「未读的**字节**」（shell 输出截断），和用户无关 |
| 客户端上报视线（`visibilitychange` / `document.hidden` / `hasFocus`） | 有，但只用于**本地**行为：页面隐藏时放开麦克风、取消录音、重试请求。**不上报服务端** |
| 客户端 ↔ 服务端的连接状态 | 只有「网络是否可用」，不是「有人在看」 |
| `delivery-accepted` 事件 | 是会话日志格式的迁移标记，**不是**「用户已接收」 |

**架构上的原因**：DSH 的 Web 客户端不向服务端回报任何「我正在看」的信号。服务端只知道事件被提交了，不知道有没有人渲染到屏幕上。

能拿到的最接近的东西，都不准：

```
user/message 事件的时间     ← 那是「发言」，用户可能看了没回
最后一条事件的时间          ← 那是 DSH 在干活，和用户无关
客户端网络在线              ← 后台标签页也算在线
```

**所以这盏灯能回答「DSH 在干什么」，不能回答「你看过了吗」。**

### 行为细节

- **呼吸灯**：只调点亮那颗灯泡的亮度，灯罩不动；关了会回到最亮档
- **提示音**：一轮完成时响一下，可关
- **大小**：小 / 中 / 大三档，切换时保持原位置
- **中英双语**：设置里切，菜单和窗口立刻跟着变
- **高 DPI**：声明了 per-monitor DPI 感知，缩放屏上字不糊
- **素材处理**：`tools/` 下的脚本负责裁侧面凸起、把未亮灯泡改成深灰、生成各亮度档
